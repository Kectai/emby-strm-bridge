# 自动字幕实现状态

适用版本：**0.2.5**。本页描述与视频共用媒体输入的字幕实现。

## Web 播放协商

已核对的 HtmlVideoPlayer 仅在宿主的 enableHlsJsPlayer 能力判断允许该视频路径时携带共享字幕协议标记，并遵循宿主独立投屏播放路径的边界。实际渲染前再确认存在 hls.js 实例；原生 HLS 不接管、不建立插件字幕会话。服务端在 MediaInfoService 为每个媒体版本生成播放方式之前，检查主输入与字幕补丁的可用状态、标记、功能开关、库范围、静态 STRM 身份、MKV 文字轨道及宿主权限。命中的版本禁用原文件 DirectPlay / DirectStream 选项，使用该浏览器原本声明支持的 MPEG-TS HLS profile；在其声明的音视频 codec 中选择 TS HLS 支持的编码，保留码率、分辨率及流复制能力限制，由 Emby 正常生成播放 URL。无需识别浏览器 User-Agent，也不改变第三方客户端的协商。

协商基于“含可用文字轨道”而非“当前已选字幕”，使默认关闭字幕后再选轨也能使用同一个视频输入。逐版本处理避免混合媒体版本互相影响。文字字幕以 External 交付给统一的 Web libass，关闭 HLS manifest 字幕分支；音视频只在宿主判断不兼容时编码，不因字幕额外强制编码或烧录。若客户端没有支持的 TS HLS 能力或用户不允许服务端播放处理，保留宿主能力判断，不伪造可播放能力。

代价是命中的 Web MKV 播放需要服务端传输视频，不再原文件 CDN 直连。单个视频 FFmpeg 解复用后同时生成 HLS 与 ASS，继续避免独立字幕下载和来源竞争。此前的 direct-play-unavailable 仅用于旧页面或不符合协商能力的请求，不作为新客户端的正常流程。所有字幕状态处理保持静默。

## 读取链路

```text
远程 MKV → Emby 视频 FFmpeg（一个媒体输入）
                          ├─ 原视频/音频输出 → Emby 播放
                          └─ 文字字幕输出 → 本地临时 ASS → 认证窗口 API → Web libass
```

`FfmpegRunner.Start(string, CancellationToken)` 在原命令后追加受控输出选项。它只接受当前有效的 ServerFfmpeg 网关票据、MKV、已知用户和播放会话、已核对的 copyts/start_at_zero 时间合同以及支持的文字轨道。原视频输出参数不修改，没有新媒体输入或独立提取进程。ASS 输出使用 `ignore_readorder=1`、`flush_packets=1`，避免跳转后事件等到 EOF 才交付。宿主仍拥有视频的进程、网络请求、节流和停止流程。

`SharedSubtitleOutput` 管理任务及临时目录。每个任务绑定用户、PlaySessionId、来源版本及完整流元数据摘要。HLS 的分片请求会先清除播放列表起点，再在启动 FFmpeg 前设置实际分片起点；播放地址在拖动时还可能保持不变，因此 URL 起点不是任务身份。按 GET 显示窗口查询同用户／会话／来源的局部输出，增量索引完整 ASS 行，分别记录最大开始与结束时间；以开始时间衡量读取进度，以结束时间判断是否可能包含当前位置的事件。结束时间很远的长事件不冒充读取进度，任何最大值都不承诺完整覆盖。局部坏文件或不可用映射不阻断其他候选，命中可用输出后不再读取无关映射。候选打开共用 10 秒截止；已完成任务缺失首分片时不再等待文件恢复。仅允许网页取整造成的不足一秒差异。每条支持的文字轨道单独输出，后续选择另一条字幕无需重新读取媒体。输出容量有界，完成任务按使用时间淘汰；运行中任务不因网页取消而删除输出文件。退出事件负责解除任务与进程的绑定。

`SharedSubtitleStream` 读取增长中的本地文件，独立保存 UTF-8 解码状态及半行；只有完整字幕行才能到达网页。MPEG-TS HLS 使用网页当前连续段实际保留的 initPTS：偏移 = TS 封装延迟 − initPTS / timescale + transcodingOffset。不能从每个新视频任务的首包重新推测 MSE 原点；同一连续段的 initPTS 会跨跳转保留。字幕起止时间使用同一个映射偏移，再按显示窗口过滤；样式、持续时长和重复事件保留。无法确认映射时返回暂时不可用，不猜测固定延迟。文件临时读到 EOF 不代表视频已经完成；进程退出后才结束流。每个读取有自己的取消和权限检查，不因换窗停止视频。

`SubtitlePlaybackService` 在原有会话合同中加入 PlaySessionId、VideoStartTicks；网页从正在播放的 URL 取得这两个值，不上传 URL 或其中的凭据。VideoStartTicks 仅用于脱敏诊断，不参与任务身份比较。NativeHlsClock 必须显式为 false，原生或未声明的时钟被拒绝；GET 由网页附带 MseTimestampOffsetTicks（transcodingOffset − initPTS / timescale）；未知连续段先等待，不沿用旧段原点。服务端校验偏移范围；这些值只控制时间映射，不改变访问权限。每次 GET 重新验证用户、库范围、媒体版本及流摘要。无法匹配任务时返回暂时不可用而非超出范围，网页最多尝试三次创建会话，取消时中止等待；若正在播放的是网关直连 MKV 地址，服务端返回 503 后不继续无效重试，静默记录 direct-play-unavailable；不会因该错误启动原生独立提取。只有明确的 outside-scope 响应才允许回退。

## 网页

主播放六处补丁与字幕三处补丁各自安装、卸载；字幕专用 ABI 失效不回滚主播放。字幕协商、Web 接管、API 与输出挂接均检查输入链路和字幕补丁所有权，后加载的竞争补丁也会停止接管。`SubtitlePatchHost` 只改写两个已核对的网页资源指纹；同时校验逐版本播放协商方法的完整参数类型、名称及补丁所有权。能力标记包装在播放器实例上，兼容 4.9 的实例方法与 4.10 的原型方法，不修改共享的原始设备 profile。`Player.js` 保留 Emby 的默认选轨及显式选择，继续使用 60 秒显示窗口、单个在途窗口、换代取消和字幕时钟偏移。创建渲染器及 worker 就绪时同步播放状态与倍速；只用 video.currentTime 作为播放时钟；帧回调只提供更新节奏，不混用 metadata.mediaTime。隔离 Octopus 及宿主的其他时间写入，暂停、缓冲和拖动同步冻结。字幕数据在下一绘制帧提交，不再固定等待 250 ms；加载、自动重试和失败均不添加画面提示，只输出固定的控制台阶段及原因码。异步启动后重新读取视频缓冲状态；每个异步响应先核对当前代际。启动或渲染失败清理自身资源并释放选轨状态，允许同轨重选；延迟清理不能删除新实例。4.10 使用 addToTrack，4.9 更新有限的 setTrack 工作集。窗口是本地数据的交付范围，不再代表一次远程解复用任务。同一 MSE 原点下的拖动保留有效窗口并合并增量数据，相同内容不重建轨道；时间原点发生变化时才换代清空。原生 HLS 不使用插件字幕渲染器。

所有浏览器采用同步的 WASM 混合渲染，保持 worker 消息顺序。宿主 Octopus 原本丢弃等于上一帧毫秒时间戳的更新；插件仅对自己的实例允许同毫秒的后续帧覆盖前帧，仍拒绝更旧的帧。取消时移除包装后的事件监听器。ResizeObserver 首次通知和未变化的尺寸不触发重复 resize，避免清空已绘制的画布。

## 验证与边界

生产字幕时间映射只接受当前 hls.js 连续段原点和已核对的 MPEG-TS 参数，缺失原点时等待，不从另一个视频任务猜测。离线首分片 PTS 解析用于 FFmpeg 时间合同验证，不据此断言原生 HLS 的浏览器呈现时钟。

维护回归覆盖实际宿主补丁安装/卸载、真实 runner 对象绑定、同一 FFmpeg 同时输出视频和 ASS、中途开始时的时间戳、未结束媒体输入的首字幕交付、UTF-8 半字符、用户/会话隔离、HLS 起点转换及窗口定位、取消和容量回收。

这里的共享是视频与字幕共用输入，不是跨用户合并视频流。Web 通过播放协商建立单个服务端视频任务，不再依赖某种浏览器恰好触发转封装。第三方客户端不携带 Web 能力标记，保持原有播放方式。冷跳转中没有被视频解复用器读到的早期长事件、复杂排版、长暂停后的任务回收和真实 Safari 端到端效果仍受 [使用说明](SUBTITLES.md) 所列边界约束。离线检查不能替代已登录网页的最终验收。

## 对照的开源实现

IINA 的 MPVController 把字幕选择和延迟交给 mpv；mpv 的 `player/sub.c` 用视频 PTS 调用字幕更新，`sub/dec_sub.c` 在同一时间轴上应用用户字幕延迟。这次沿用“以画面时间驱动字幕”的原则，在 Web 端补齐 worker 初始状态、倍速、帧回调和缓冲事件；保留浏览器 HLS 必需的时间映射。

参考：[IINA MPVController](https://github.com/iina/iina/blob/v1.4.4/iina/MPVController.swift)、[mpv 字幕更新](https://github.com/mpv-player/mpv/blob/master/player/sub.c)、[mpv 字幕时间转换](https://github.com/mpv-player/mpv/blob/master/sub/dec_sub.c)。

窗口响应固定声明 `X-StrmBridge-Subtitle-Window: partial`。输出任务结束只说明一次视频读取结束，不能证明显示窗口已完整；网页保留已交付数据并在 EOF 后退避续查（1–8 秒），临时读取错误使用同样的恢复机制。不可恢复的权限、来源及数据错误不会无限重试。运行中任务仍限 8 个，保留输出单独限制为 64 个及已完成数据 64 MiB 回收目标，避免第九次跳转直接丢掉先前缓冲对应的字幕。

原生 HLS 在冷分片与旧缓冲间跳转时，其浏览器映射无法从某个 FFmpeg 任务的首 PTS 唯一确定。插件不再宣告这一路径的字幕支持；普通支持 MSE 的网页沿用宿主 hls.js，继续使用可观测的实际原点。
